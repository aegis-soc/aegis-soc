## 1. 快速上手

### 1.1 登录

1. 浏览器打开 `http://<部署机IP>:8080`；
2. 默认账号 `admin / Admin@123456`（**首次登录强制改密**，请立即设置强口令）；
3. 右上角可切换中文/English（语言选择存本地）。

### 1.2 三种角色

| 角色 | 能做什么 |
|---|---|
| 系统管理员（admin） | 全部功能，含系统设置、数据源配置、熔断开关、用户管理 |
| 安全运营（operator） | 告警处置、黑白名单、设备/策略/任务、巡检执行、行为分析、对话 |
| 只读审计员（auditor） | 只读查看所有运营数据 + 对话，不能改任何配置 |

角色由管理员在数据库 `system_role` 表维护（当前无界面）；账号在「系统设置」页查看。

### 1.3 页面导览

| 菜单 | 页面 | 用途 |
|---|---|---|
| 首页大盘 | Dashboard | 今日/累计告警、黑名单状态、设备在线、任务统计、风险分布 |
| AI 巡检 | Inspection | 平台健康体检报告（每天 08:30 自动 + 手动触发） |
| 日志巡检 | Patrol | Graylog 三流日志的确定性规则扫描（5 分钟一轮） |

| IP 黑名单 / 域名黑名单 | Blacklist | IOC 管理、导入导出 |

## 2. 日常运营操作

### 2.1 查看与处置告警（告警中心）

1. 告警由 Graylog Webhook 自动推入（也可「通用告警」接口对接 ElastAlert/Suricata）；
2. 列表支持按状态/来源系统/关键词筛选，点详情看原始载荷与候选 IOC；
3. 告警触发封禁由**策略**自动判定（见 2.4），不需要人工逐条点封。

### 2.2 黑名单与白名单

**IP 黑名单**：
- 「新增」填 IP/CIDR，可选「立即下发封禁」；归属地自动查询（离线库）；
- 「导入」支持 CSV 文件（≤2MB）或粘贴文本，单次 ≤5000 行；命中白名单的自动跳过；
- 「导出」CSV（Excel 直接打开不乱码）；
- 删除记录 = 自动生成解封任务并联动同值兄弟记录。

**IP 白名单**（优先级最高，任何封禁动作前先检查）：
- 支持单 IP 和 CIDR（IPv4 最大 /8）；
- 新增/导入时可选择「联动解封网段内已有黑名单」；
- 典型用途：公司出口 IP、办公网段、扫描器自身。

> ⚠️ 白名单是安全兜底：误把攻击 IP 加白会导致该 IP 永不被封。操作留审计。

### 2.3 设备与插件

1. 「插件管理」看 8 个内置插件（深信服 IPS、启明 IPS/USG、PaloAlto、阿里云 WAF、华为/H3C SSH 防火墙、通用 REST、mock 演示）；
2. 「设备管理」→ 新建设备：选插件、按表单填地址与凭据（凭据以环境变量引用，不落库明文）；
3. 「测试」按钮做连通性验证，状态回写设备列表；
4. 接入新类型设备需要开发插件（见 `docs/plugin-dev.md`），平台无需改代码。

### 2.4 策略（自动封禁规则）

默认策略 `default-auto-block`：critical/high/medium 风险、置信度 ≥60、封 2 小时。可新建策略调整：

| 配置项 | 说明 |
|---|---|
| 条件 conditions | 匹配哪些告警（来源/类型/风险级） |
| threshold_count × window_minutes | 时间窗内出现 N 次才封（防误封偶发） |
| min_confidence | 最低置信度 |
| block_duration | 封禁时长 |
| require_approval | 开启后任务先进入审批，人工通过才下发 |
| target_plugins | 封到哪几台设备 |

策略按 priority 从高到低匹配，第一个命中生效。

### 2.5 任务日志（封禁/解封执行）

- 任务状态：PENDING → RUNNING → SUCCESS / FAILED / RETRY / CANCELED（审批的还有 APPROVING/REJECTED）；
- 失败任务可「重试」（重新派发）；详情里看每次尝试的请求/响应留痕（不含凭据）；
- 需审批的任务在列表里「通过/拒绝」。

### 2.6 操作审计

所有写操作（增删改、封禁、审批、配置变更、对话提问）自动留痕：操作人、角色、操作类型、目标、来源 IP。只读，管理员按操作类型/操作人筛选。

## 3. 巡检能力

### 3.1 AI 巡检（平台体检）

- 每天 08:30 自动执行，也可「立即执行」；
- 输出 0–100 加权健康分（ok=100/warn=55/fail=0），**安全效果层权重更高**（封禁缺口 2.0、处置率 2.0）；
- 12 个检查项覆盖：设备连通、三流覆盖、封禁缺口、处置率、跨日持续攻击、黑名单健康、到期解封、任务队列、策略覆盖、白名单、攻击态势、系统风险；
- 可选配 LLM 做报告总结（没配或失败自动回退规则总结，不影响分数）。

### 3.2 日志巡检（Graylog 三流扫描）

**怎么工作**：beat 每分钟唤醒，按页面配置的间隔（默认 5 分钟）真跑一轮——通过 Graylog MCP 只读拉取 IPS / WAF / 零信任三条流窗口内日志，跑 11 条确定性规则，产出候选 IP 列表与处置建议（dry-run 模式只建议不下发）。

**规则一览**：

| 规则 | 触发条件 |
|---|---|
| IPS 告警未阻断 | IPS 动作=observe/audit 且严重级非低 |
| WAF 放行/仅记录 | WAF 动作=observe/pass |
| WAF 拒绝高频 | 同 IP REJECT ≥ 5 |
| 登录爆破 | 同 IP 登录页 REJECT ≥ 10 |
| 零信任多域名扫描 | 同 IP 访问 ≥ 4 个不同域名 |
| 零信任目录扫描 | ≥ 20 个不同 URI 且 ≥ 15 个路径前缀 |
| WAF 伪造源 IP | XFF 链尾 ≠ 直连 IP |
| 零信任认证爆破 | 认证重定向 ≥ 10 次 |
| 高频访问 | 同 IP 日志 ≥ 50 条 |
| 跨流命中 | 同 IP 出现在 ≥ 2 条流 |
| 情报命中 | 情报标签命中或威胁分 ≥ 60 |

内网 IP、白名单 IP、已封 IP、24h 内重复候选自动跳过（会显示跳过原因）。

### 3.3 数据源配置（管理员）

「数据源」页管理四类源（ips / waf / ztna / nta）的字段契约。**三个关键配置**：

1. **stream_id**：该源对应 Graylog 里的流 ID；
2. **必填字段（required_fields）**——保存时强制校验：
   - 🔴 `ts`（日志时间）与 `src_ip`（来源 IP）**必填**，缺失保存直接被拒（时间窗与 IP 聚合静默失效的根因）；
   - 🟡 建议字段：ips/waf 填 `action`；ztna 填 `username`、`display_name`、`ua_class`、`dst_domain`、`l7_app_request_type`（缺了对应功能降级，页面有黄色提示）；
   - 每个字段显示解析状态：`字段 → Graylog列名（解析方式）`；
3. **值映射（value_mapping）**——不同厂商动作值不同（如绿盟 IPS `1/3/8`=告警/阻断/封禁，WAF 是 `permit/drop/block`），把厂商枚举映射到标准词表（observe/audit/block/ban/pass/reject）。**数字枚举必须显式配置，系统不做猜测**。右侧下拉即选标准值；
4. **白名单（ip_whitelist）**：源级额外免封 IP。

改完用「探测」按钮试取一轮，能看到实际下发的 MCP 参数与服务端原始返回，用于验证字段对不对。

## 4. 行为分析（LBA）

### 4.1 登录行为分析页

1. 进入页面**先选时间范围**（近 1 小时 / 1 天 / 7 天按钮），点击才取数——不会自动打 Graylog；
2. KPI：活跃用户数、设备数、待核查、高风险用户，下方一行灰字显示**统计窗口、取回条数、数据跨度、来源**；
   - `来源 store` = 读本地预聚合表（快）；`来源 live` = 实时聚合（采集器未运行时的兜底）；
   - 若三个窗口数据一样且数据跨度只有几小时——是日志本身积累时间短，等数据即可；
3. 异常用户列表：第一列用户 ID、第二列用户名，风险等级筛选；点行进详情。

### 4.2 用户详情页

- 用户画像：请求数、失败数、IP 数、国家数、设备数、风险等级；
- 时间线：逐条访问记录（时间、**绿色域名（dst_domain）**、URL、方法、状态、来源 IP）；
- 风险判定口径（启发式，仅提示）：7 天跨 IP ≥5 / 跨国家 ≥2 / 失败 ≥10 → 高风险；跨 IP ≥3 / 设备 ≥3 → 中风险。**内网 IP 不计入**跨 IP/跨国风险（轨迹里保留并标 internal）。

### 4.3 采集器（管理员）

后台每 5 分钟自动增量采集零信任日志并预聚合落库，无需人工干预。排查入口：

```bash
curl -H "Authorization: Bearer <token>" http://127.0.0.1:8080/api/v1/lba/collect/status
```

返回水位（watermark）、最近一轮状态（last_status=ok/error）与预聚合行数。页面 `来源 live` 长期不变成 `store`，说明 worker/beat 没起来或采集报错，看 `docker compose logs worker --tail 50`。

## 5. 人机对话

在「人机对话」页用自然语言提问，例如：

- 「最近 24 小时哪些 IP 未被拦截？」
- 「今天黑名单新增多少条？」
- 「零信任流里 oa.xx.com 的访问集中在哪些用户？」

特性与边界：
- **确定性查询**：不依赖大模型，解析不了会反问澄清，不会编造答案；
- 只读：只能查，不能改配置/下发封禁；
- 日志类问题窗口最多 7 天，库类最多 365 天，单问句最多 3 个子查询；
- 限流 20 次/分钟/用户；
- 回答附带数据来源与查询轨迹（trace），审计留痕；
- 询问「你能查什么」看能力清单与推荐问法。

## 7. 部署与运维

### 7.1 日常升级（拉新版）

```bash
cd ~/aegis-soc
git pull && docker compose up -d --build
```

- **api / worker / beat / frontend 都要重建**（只重建 frontend 会导致新旧代码混跑出诡异问题）；
- 新版本新增表会在 api 启动时**自动补建**（幂等，不动已有数据）；但「已有表加列」需按版本说明手工执行 `sql/migrate_*.sql`；
- 升级后看 `docker compose ps` 确认无 restarting，浏览器 Ctrl+F5 强刷。

### 7.2 低内存环境

内存 ≤2.5GB 用 `docker compose -f docker-compose.2g.yml up -d`。

### 7.3 数据备份

```bash
docker exec aegis-soc-mysql-1 mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" aegis_soc > backup_$(date +%F).sql
```

建议每日备份；恢复：停 api/worker/beat → 导入 → 起服务。

### 7.4 故障排查速查（FAQ）

| 症状 | 排查 | 常见根因 |
|---|---|---|
| api 容器反复重启 | `docker compose logs api --tail 50` | MySQL 未就绪；**DB 密码含特殊字符（如 @）未编码**——用 `DB_HOST/DB_USER/DB_PASSWORD` 分量式配置（自动编码），别手拼 DATABASE_URL |
| 登录 401 | — | 区分两个密码：MySQL 密码 ≠ 平台登录密码（`BOOTSTRAP_ADMIN_PASSWORD`，只在首次建 admin 时生效）。改 .env 对已存在的 admin 无效 |
| 页面 500 | 看页面 toast 的异常摘要（新版直接显示异常类+原因）；再 `docker compose logs api` | 老库缺新表（升级到含自动补表的版本）；接口异常 |
| 某页无数据、无请求 | F12 → Network 看请求是否发出、状态码 | 前端缓存旧 JS → Ctrl+F5；菜单接口 403 → 角色权限不足 |
| 行为分析三个时间窗数据一样 | 看 KPI 下诊断行的「数据跨度」 | 数据跨度短 = 日志积累时间不够（非 bug）；跨度长且条数一样 = 提 bug |
| 行为分析一直「来源 live」 | `GET /lba/collect/status` 看 last_status | worker/beat 未起；采集报错看 worker 日志 |
| 日志巡检「降级/失败」 | 数据源页「探测」看原始返回 | stream_id 错；MCP 地址/ token 错；字段缺失率高 |
| 封禁没下发 | 任务日志看任务状态与失败原因 | 白名单命中；策略阈值未达；设备能力未配；熔断开启；设备连不通 |
| 误封了 IP | 删黑名单记录（自动解封）或加白名单后联动解封 | — |
| Graylog 告警没进来 | `docker compose logs api | grep alerts`；检查 Secret 与来源 IP 白名单 | Webhook URL/Secret 错；api 所在网段不在告警白名单 |

### 7.5 冒烟验收

部署后跑 `python3 scripts/smoke_test.py`（18 项自检），或按 `docs/verify.md` 人工验收。
