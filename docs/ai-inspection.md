# AI 巡检（AI Inspector）

「AI 巡检」是平台的主菜单功能：对 SOAR 平台做一次**只读体检**，输出加权健康分、
逐项结论、可执行建议与总结，报告落库可回看。

v2 起巡检从「平台体检」升级为**两层视角**——先回答「防护到底有没有生效」，
再回答「平台自身是否健康」。设计口径参考 `graylog-security` 设计文档
（三流 IPS/WAF/ZTNA、R0-R7 规则、「该封未封」缺口分析、跨日持续攻击）。

## 两层检查项（12 项）

### 安全效果层

| # | 检查项 | 判定逻辑 | 严重场景 |
|---|---|---|---|
| 1 | **三流覆盖** | 24h 内 IPS / WAF / ZTNA 哪几路有记录、最近一次是什么时候 | 仅一路有数据 = warn；核心流缺失 = warn |
| 2 | **封禁缺口** | 24h 检出 IP 里「该封但没封」的数量与原因归因，详见下表 | 处置率 <70% = fail，<90% = warn |
| 3 | **处置率** | 近 7 日按自然日的处置率趋势 + 24h 封禁量/峰值小时/重复下发 | 7 日均值 <60% = fail，<85% = warn；今日骤降 15pt = warn |
| 4 | **持续攻击源** | 近 7 天跨 ≥3 天反复出现的 IP（对应 graylog 规则 R5） | 存在即 warn，并给出建议封禁时长 |

### 平台运行层

| # | 检查项 | 判定逻辑 | 严重场景 |
|---|---|---|---|
| 5 | **设备连通性** | 逐台调用插件 `test_connection`，结果回写设备状态 | 全部不可达 = fail |
| 6 | **黑名单健康** | 生效数、24h 新增、拦截留痕数、永久封禁占比 | 无生效记录 = warn；有永久封禁 = warn |
| 7 | **到期解封风险** | 已过期但仍 `active` 的记录数（解封链路失灵的直接信号） | 有逾期记录 = fail |
| 8 | **任务队列** | 卡住（PENDING/RETRY）任务数、24h 失败率 | 失败率 ≥50% = fail |
| 9 | **策略覆盖** | 启用策略数、24h 告警的 ignored 占比 | 无启用策略 = fail；ignored ≥60% = warn |
| 10 | **白名单风险** | 网段宽度小于 /16 的显式 CIDR | 过宽 = warn |
| 11 | **攻击态势** | 7 天 top 攻击来源国、反复命中（≥3 次）IP | 仅展示，恒为 ok |
| 12 | **系统风险** | 熔断开关、归属地库就绪、插件注册一致性 | 熔断开启 = fail |

## 封禁缺口：这个 IP 明明在攻击，为什么没封？

这是巡检最核心的一项。它对 24h 内的告警做归因，直接指出「没封」的原因：

| 归因 | 含义 | 是否算缺口 | 处理方向 |
|---|---|---|---|
| 未命中策略 | 告警进了平台但没有任何启用策略接住 | 是 | 补策略 / 放宽条件 |
| 下发未生效 | 策略命中但没有生效黑名单（设备不可达、凭据错、任务失败） | 是 | 查设备连通性与任务日志 |
| 熔断期间留痕 | 全局熔断开启，所有告警只留痕 | 是 | 恢复后人工复核这批攻击源 |
| 未达阈值 | 单次告警没达到策略阈值 | 是 | 降阈值 / 缩短统计窗口 |
| 待处理 / 其他未处置 | 仍 pending 或未归类 | 是 | 人工看告警详情 |
| 白名单豁免 | 受保护地址（含内网、文档地址）刻意不封 | **否**（设计内豁免） | 复核白名单范围是否过大 |
| 地址校验拒绝 | 内网 / 保留地址 / 非法格式被硬性拒绝 | **否**（设计内豁免） | 无 |

**处置率 = 已封禁 IP / (已封禁 IP + 可处置缺口 IP)**，分母**不含豁免项**。
不这样定义的话，内网扫描一多，处置率会被永久拖低，指标就失去意义。

## 加权健康分

各项得分仍为 ok=100 / warn=55 / fail=0，但改为按权重加权平均：

| 权重 | 检查项 |
|---|---|
| 2.0 | 封禁缺口、处置率 |
| 1.5 | 设备连通性、到期解封风险 |
| 1.0 | 三流覆盖、持续攻击源、黑名单健康、任务队列、策略覆盖、系统风险 |
| 0.5 | 白名单风险、攻击态势 |

设备全在线、任务全成功，但该封的一个都没封时，健康分不应是满分——权重就是这么定的。

## 报告里的 metrics（KPI 快照）

每次巡检落库时同时写入 `inspection_report.metrics`，前端 KPI 条与历史表格直接取这里：

```json
{
  "detection_rate_24h": 0.82, "detection_rate_7d": 0.86,
  "detected_ips_24h": 45, "blocked_ips_24h": 37, "gap_ips_24h": 8, "exempt_ips_24h": 5,
  "persistent_ips": 3, "active_sources": 3, "core_sources": 3, "missing_sources": [],
  "blocked_24h": 41, "peak_hour": "09:00", "peak_count": 12,
  "previous_score": 78, "score_delta": 4,
  "trend": [{"date": "2026-11-01", "detected": 40, "blocked": 35, "exempt": 4, "rate": 0.97}]
}
```

`score_delta` 只在与上一次巡检对比时出现；首次巡检没有基准。

## 触发方式

- **手动**：页面右上角「立即巡检」，同步返回完整报告；
- **定时**：Celery Beat 每天 08:30 自动跑一次（`aegis.run_inspection`），报告落库供回看。

## AI 总结：增强而非依赖

- 默认由**内置规则**拼接中文总结（列出问题与建议，永远可用）；
- 配置 OpenAI 兼容接口后自动升级为大模型总结（界面显示「AI 生成总结」标签）。
  提示词会带上 metrics 与缺口语境，要求先判断「防护是否生效」再给动作建议：

```bash
# .env 追加（可选）
AI_LLM_BASE_URL=https://api.openai.com/v1   # 任何 OpenAI 兼容接口均可
AI_LLM_API_KEY=sk-xxxx
AI_LLM_MODEL=gpt-4o-mini
```

LLM 调用失败（超时 20s / 网络异常 / key 无效）自动回退规则总结，**巡检结果永远可用**；
未配置时不会发起任何网络请求。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/v1/inspections/run` | `inspection:run` | 立即巡检（前端请求放宽到 90s：含逐台设备连通测试） |
| GET | `/api/v1/inspections/latest` | `inspection:read` | 最近一次报告（从未巡检返回 null） |
| GET | `/api/v1/inspections/reports` | `inspection:read` | 历史报告分页（含 metrics，用于趋势与环比） |
| GET | `/api/v1/inspections/reports/{id}` | `inspection:read` | 报告详情 |

权限：`admin` 全量；`operator` 可跑巡检；`auditor` 只能看报告（见 `sql/seed.sql`，老库执行 `sql/migrate_20261107_inspection.sql` 补权限与 metrics 列）。

## 设计约束

- **只读体检**：除设备状态回写（与手动「测试连接」一致）外不改变任何封禁状态；
- **可降级**：任何单项检查抛异常 → 该项置 fail 并给出排查建议，整场巡检不中断；
  指标汇总失败时报告照常落库，只是 `metrics` 为空；
- **指标只跑一遍**：同一次巡检内缺口/趋势/来源/节奏的查询通过共享上下文复用，
  不会因为 12 项检查而重复扫表；
- **数据全来自平台自身**：设备表、任务表、黑名单流水、告警、白名单、策略。

## 常见问题

| 现象 | 处理 |
|---|---|
| 「到期解封风险」fail：有逾期记录 | 本地 / 测试环境没起 Celery Beat 属正常（到期解封依赖 beat 每分钟扫描）；生产检查 worker 与 beat 容器是否在跑 |
| 「三流覆盖」常年缺 ZTNA | 环境里没有零信任网关时会一直提示；确认不需要后可在 `security_metrics.CORE_SOURCES` 里调整期望的三路 |
| 处置率显示「—」 | 24h 内既没有封禁也没有可处置缺口（例如只有白名单/内网告警），分母为 0，属正常 |
| 「封禁缺口」fail 但黑名单看着很多 | 缺口看的是「检出 IP 的封禁比例」，不是黑名单总量；点开原因分布看是哪一类没接住 |
| 设备连通性大量不可达 | 未配置凭据环境变量或网络不通；逐台「设备管理 → 测试连接」看具体原因 |
| 总结没有「AI 生成总结」标签 | 未配置 `AI_LLM_*`，当前为规则总结；配置后重启后端即可 |
| 想跳过某项检查 | 注释掉 `app/services/inspector.py` 中 `CHECKS` 列表对应项即可 |
