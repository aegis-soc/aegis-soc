# 界面中英文切换

前台所有**界面文案**支持中英双语，侧边栏底部一键切换。默认中文，不跟随浏览器语言。

```
侧边栏底部：  v1.0.0 · a1b2c3d      中文 / EN
登录页右上角：                       中文 / EN
```

## 一条边界：什么翻译，什么不翻译

i18n 最容易出问题的地方不是翻译质量，而是**把不该翻的东西翻了**。本项目的边界：

| 通路 | 例子 | 是否翻译 | 落点 |
|---|---|---|---|
| 界面文案 | 菜单名、表头、按钮、校验提示、空状态 | ✅ 翻译 | 前端语言包 |
| 枚举显示值 | `active` → 启用 / Active；`BLOCK` → 封禁 / Block | ✅ 翻译 | 前端语言包，**值本身不变** |
| 后端校验报错 | `BizError("设备编码已存在")` | ❌ 暂不翻译 | 后端口径（见「本轮不做」） |
| 业务数据 | IP、域名、设备名、备注、告警原文 | ❌ 不翻译 | 数据库原值 |
| 归属地 | `中国` / `美国`（ip2region 写入的中文） | ⚠️ 仅显示映射 | 值仍是中文原值 |
| 系统生成语句 | 巡检结论、人机对话的事实句 | ❌ 暂不翻译 | 服务端模板（见「本轮不做」） |

两条硬规则，写代码时不要破坏：

1. **枚举值以英文 code 存储**（`active` / `BLOCK` / `online` / `PENDING`），只在显示层 `t()`。这样切换语言**不会清空已选中的筛选条件**，也不会让 URL 参数、审计日志、接口契约随语言变化。
2. **未知枚举原样显示**。`pick()` 里先 `te()` 判断，语言包缺 key 时显示原值而不是 `blacklist.status.xxx` 这种裸 key——后端加了新状态、前端没跟上时，页面还能看。

## 目录结构

```
frontend/src/i18n/
├── index.js                 # createI18n + 语言包自动收集 + 跟随 store.locale
└── locales/
    ├── zh-CN/               # 一个页面一个文件，文件名 = 命名空间
    │   ├── common.js        #   共享词汇：动作 / 标签 / 单位 / 提示 / 角色
    │   ├── menu.js          #   菜单与面包屑
    │   ├── layout.js  login.js  enums.js
    │   ├── dashboard.js  alerts.js  audit.js  plugins.js  policies.js
    │   ├── tasks.js  whitelist.js  blacklist.js  devices.js
    │   └── inspection.js  chat.js  patrol.js  system.js
    └── en-US/               # 文件名与 zh-CN 一一对应
```

`locales/<lang>/<ns>.js` 里 `export default { ... }`，键名在页面里就是 `<ns>.<key>`：

```js
// locales/zh-CN/alerts.js
export default {
  title: '告警中心',
  col: { receivedAt: '接收时间', risk: '风险' },
  test: { accepted: '告警已接收，生成 {n} 个任务' },
}
```

```vue
<script setup>
import { useI18n } from 'vue-i18n'
const { t, te } = useI18n()
</script>

<template>
  <h2>{{ t('alerts.title') }}</h2>
  <el-table-column :label="t('alerts.col.receivedAt')" />
</template>
```

## 怎么加内容

### 给现有页面加一句文案

1. `zh-CN/<ns>.js` 加 key，`en-US/<ns>.js` 加同名 key（**两边必须同时加**）
2. 组件里 `t('<ns>.<key>')`，模板与 `<script>` 里都能用（`globalInjection` 已开，模板可直接 `$t`）

不要用中文字符串当 key。`t('保存')` 这种写法看着省事，改文案就得改代码，且两个语言的 key 会打架。

### 加一个页面

新建 `views/Xxx.vue`，配 `locales/zh-CN/xxx.js` + `locales/en-US/xxx.js`（文件名一致），
然后在**两处**登记：`router/index.js` 的 `meta.titleKey`、`MainLayout.vue` 的 `titleKey`。语言包本身不用注册——`import.meta.glob` 会自动收。

### 加一门语言

1. 复制 `locales/zh-CN/` 为 `locales/ja-JP/` 并翻译
2. `i18n/index.js` 的 `messages` 加一组，`glob` 换成通用匹配
3. `store/index.js` 的 `locale` 白名单放行新值，`MainLayout.vue` / `Login.vue` 的切换器加一项

`fallbackLocale: 'zh-CN'` 已经兜住：新语言缺的 key 回退中文，不会白屏。

## 实现要点

| 点 | 做法 | 为什么 |
|---|---|---|
| 语言包注册 | `import.meta.glob('./locales/<lang>/*.js', { eager: true })` | 新增页面只丢文件，不用维护注册表 |
| 默认语言 | 固定 `zh-CN`，不读 `navigator.language` | 运维的服务器/笔记本常是英文系统，跟随浏览器等于默认给英文 |
| 持久化 | `localStorage.gl_lang`，**只认 `en-US`**，其他值一律回落中文 | 手改 localStorage 塞脏值也不会白屏 |
| 切换生效 | `watch(() => store.locale)` → `i18n.global.locale.value` + `<html lang>` | 不刷新页面，且 `lang` 属性正确（影响字体、拼写检查、读屏） |
| 回退 | `fallbackLocale: 'zh-CN'` | 漏译时显示中文，不是裸 key |
| 开发期告警 | `missingWarn` / `fallbackWarn` 只在 DEV 打开 | 生产控制台不刷屏 |
| Element Plus | `<el-config-provider :locale>`（`zh-cn` / `en`） | 分页「条/页」、日期选择器、`el-empty` 一并跟随 |
| 时间格式 | `toLocaleString(store.locale === 'en-US' ? 'en-US' : 'zh-CN')` | 中英的日期顺序不同 |

`App.vue`：

```vue
<el-config-provider :locale="elLocale">
  <router-view />
</el-config-provider>
```

## 自检

```bash
cd frontend && npx vite build       # 有裸 key 会在构建产物里留下未替换文案
```

跑起来后开 DevTools Console：DEV 模式下漏 key 会打 `[intlify] Not found 'xxx' key in 'zh-CN' locale messages`。
`fallbackWarn` 同理——它提示「英文缺这个词，回退到中文了」，是补翻译的清单。

比对两侧 key 是否齐（一次性脚本）：

```js

```

## 本轮不做

| 项 | 内容 | 为什么不做 |
|---|---|---|
| P3 | 后端 51 处 `BizError` 文案改错误码，前端按码映射 | 要动所有接口的错误契约，收益远低于界面文案；且错误码要长期维护 |
| P4 | 巡检结论 / 人机对话事实句的服务端双语 | 这两块是**模板拼出来的句子**，得在服务端按 `Accept-Language` 出两套文案，涉及结论生成逻辑 |
| P5 | CI 校验语言包 key 一致、无中文残留 | 只有两个人维护时手工比对够用；等外部 PR 多了再上 |

真要推进，顺序建议 P3 → P5 → P4：P3 影响面最大但机械，P5 是防回归的护栏，P4 最贵。
